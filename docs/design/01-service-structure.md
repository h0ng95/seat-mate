# 01. 전체 서비스 구조

## 목표

`내 반에 앉아봐`는 로그인 없이 생년월일로 좌석과 관계를 정하고, 링크를 통해 3x3 교실을 함께 채우는 모바일 우선 Flutter Web 서비스다.

핵심 성공 기준은 다음과 같다.

- 첫 화면에서 5초 안에 서비스 목적과 다음 행동을 이해한다.
- 같은 입력은 언제나 같은 캐릭터, 관계, 좌석 후보를 만든다.
- 친구가 참여할수록 교실 결과 화면의 공유 가치가 커진다.
- 개인정보는 별명과 생년월일만 최소 저장한다.
- 360px, 390px, 430px 모바일 화면에서 주요 흐름이 완결된다.

## 사용자 역할

### 생성자

1. 별명과 생년월일을 입력한다.
2. 자신의 자리 성향과 좌석을 확인한다.
3. 교실을 생성하고 고유 링크를 공유한다.
4. 완성되어 가는 교실을 다시 방문해 확인한다.

### 참여자

1. 공유 링크로 기존 교실을 연다.
2. 현재 좌석표를 바로 확인한다.
3. 별명과 생년월일을 입력한다.
4. 생성자와의 관계 및 자신의 좌석을 확인한다.
5. 결과를 공유하거나 자신의 반을 만든다.

## 제품 영역

| 영역 | 책임 |
| --- | --- |
| 진입 | 서비스 소개와 반 만들기 CTA 제공 |
| 반 생성 | 입력 검증, 생성자 성향/좌석 계산, 교실 저장 |
| 교실 | 3x3 좌석표 조회, 정원 및 신규 참여 상태 표시 |
| 참여 | 중복 확인, 관계 계산, 빈 좌석 결정, 저장 |
| 결과 | 관계 설명과 재미용 지표 표시, 선택 좌석 강조 |
| 공유 | 링크 공유, 클립보드 대체, 결과 이미지 저장 |
| 운영 상태 | 로딩, 잘못된 링크, 네트워크 오류, 정원 초과 처리 |

## 페이지 구조

| 경로 | 목적 | 주요 상태 |
| --- | --- | --- |
| `/` | 짧은 랜딩 | 기본 |
| `/create` | 생성자 입력 및 자리 찾기 | 입력, 계산 중, 결과 확인, 저장 중, 오류 |
| `/class/:shareCode` | 교실 조회와 친구 참여 | 로딩, 조회 성공, 참여 폼, 배치 중, 정원 완료, 오류 |

개인 결과는 MVP에서 별도 경로를 만들지 않고 교실 페이지의 BottomSheet로 제공한다. 공유 요구가 커지면 `/result/:shareCode/:memberId`를 추가한다.

## 계층별 책임

### Presentation

- 반응형 화면과 접근 가능한 입력 UI
- Riverpod 상태 구독 및 사용자 이벤트 전달
- 좌석 이동, 신규 참여, 반 완성 애니메이션
- BottomSheet, 공유 시트, 오류 복구 CTA

### Application

- 반 생성과 참여 유스케이스 조합
- 입력 정규화 및 검증
- 로딩/성공/실패 상태 전환
- 저장 전 정원과 중복 조건 확인

### Domain

- 생년월일 기반 stable hash
- 생성자 자리 성향 계산
- 관계 유형 계산
- 관계별 선호 좌석과 충돌 해결
- 캐릭터 파츠 계산

Domain 로직은 Flutter 위젯과 Supabase에 의존하지 않는 pure function으로 유지한다.

### Data

- Supabase 테이블 및 RPC 호출
- DTO와 Domain 모델 변환
- 네트워크 오류를 앱 오류 타입으로 변환
- 동일 교실의 동시 참여를 DB 트랜잭션으로 직렬화

## 핵심 상태 모델

```text
Classroom
  id, shareCode, owner, ownerSeat, members, createdAt

Person
  id, nickname, birthDate, characterSeed

ClassroomMember
  person, seatIndex, relationshipType, createdAt

SeatAssignment
  seatIndex, relationshipType, relationshipMetrics
```

## 주요 제약

- 좌석 인덱스는 0~8이며 한 교실에서 유일하다.
- 생성자를 포함해 최대 9명이다.
- 동일한 정규화 이름과 생년월일은 같은 교실에 한 번만 참여한다.
- 클라이언트 계산은 즉시 미리보기를 제공하지만 최종 좌석 확정은 DB가 담당한다.
- 만석 교실은 읽을 수 있지만 참여 폼 대신 `내 반 만들기` CTA를 노출한다.
- 성별, 이메일, 전화번호, 학교, 지역 정보는 수집하지 않는다.

## 비기능 원칙

- 결과 교실 화면을 가장 먼저 최적화한다.
- 첫 진입에 필요하지 않은 저장/공유 기능은 지연 로드한다.
- 기본 Material 모양을 그대로 노출하지 않고 서비스 테마를 적용한다.
- 장애 시 기본 Flutter 오류 대신 원인과 복구 행동이 있는 화면을 제공한다.
- 알고리즘 버전을 저장해 추후 규칙 변경 후에도 기존 결과를 재현할 수 있게 한다.
