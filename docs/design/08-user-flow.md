# 08. 전체 사용자 흐름

## 핵심 바이럴 루프

```text
랜딩
  -> A가 반 생성
  -> A의 교실 결과
  -> 링크 공유
  -> B가 교실 방문
  -> B가 빈자리에 참여
  -> B의 관계 결과
  -> B가 결과 공유 또는 자신의 반 생성
  -> 새로운 공유 링크
```

모든 주요 결과 화면에는 `공유`와 `내 반 만들기`가 함께 존재한다. 참여자의 결과를 막다른 화면으로 만들지 않는다.

## 1. 랜딩

경로: `/`

```text
페이지 진입
  -> 서비스명과 한 줄 설명 표시
  -> 내 반 만들기 CTA
  -> CTA tap
  -> /create
```

첫 화면 문구:

```text
내 반에 앉아봐
친구들 생일을 모으면 우리만의 반이 완성돼요.
[내 반 만들기]
```

- 가짜 참여자 수를 표시하지 않는다.
- 링크 수신자는 랜딩을 거치지 않고 `/class/:shareCode`로 바로 간다.
- 긴 사용법, 관계 목록, 사주처럼 보이는 설명은 넣지 않는다.

## 2. 생성자 입력

경로: `/create`

```text
별명 입력
  -> 생년월일 입력
  -> 내 자리 찾기
  -> 클라이언트 검증
    -> 실패: 필드 오류, 입력 유지
    -> 성공: 자리 계산 상태
```

검증:

- 별명: trim 후 1~12 grapheme
- 생년월일: 실제 달력 날짜
- 생년월일: 1900-01-01 이상, 오늘 이하
- 안내: `실명 대신 별명을 사용해도 좋아요.`

모바일 date input이 브라우저별로 다르므로 연/월/일 입력과 native date picker 중 접근성이 좋은 구현을 검증 후 선택한다.

## 3. 생성자 자리 계산

```text
내 자리 찾기
  -> 입력을 canonical form으로 변환
  -> 생성자 성향 및 좌석 계산
  -> 1.2~1.8초 진행 연출
  -> 자리 결과 미리보기
```

진행 문구는 짧게 순환한다.

```text
칠판 닦는 중...
책상 옮기는 중...
당신의 자리를 찾는 중...
```

계산은 즉시 끝나더라도 첫 전환이 너무 번쩍이지 않도록 최소 700ms만 유지한다. 네트워크 저장 전의 미리보기임을 UI에서 기술적으로 설명하지 않는다.

## 4. 생성자 결과와 교실 생성

```text
재홍님의 자리는
창가 2열 가운데 자리

창가 감성러
혼자 멍 때리는 시간을 좋아하지만
친해지면 장난기가 많은 타입.

[이 자리로 반 만들기]
```

```text
이 자리로 반 만들기
  -> 버튼 중복 tap 차단
  -> create_classroom RPC
    -> 성공: /class/:shareCode로 replace 이동
    -> 네트워크 오류: 결과 유지, 다시 시도
    -> 입력 오류: 해당 입력 화면으로 복귀
```

브라우저 back으로 저장 요청을 반복하지 않도록 성공 후 history replace를 사용한다.

## 5. 생성자의 교실 결과

경로: `/class/:shareCode`

```text
교실 조회
  -> 생성자 한 명이 앉은 3x3 교실
  -> 친구 초대 문구
  -> 링크 공유하기
```

생성자 여부를 로그인으로 판별할 수 없으므로 모든 방문자가 참여 폼을 볼 수 있다. 방금 생성한 브라우저에는 로컬에 `createdClassroomShareCode`를 저장해 생성자 맞춤 CTA를 보여줄 수 있지만 보안 권한으로 사용하지 않는다.

## 6. 링크 공유

```text
링크 공유하기
  -> Web Share API와 사용자 gesture 사용 가능?
    -> 예: 시스템 공유 시트
    -> 아니오: URL 클립보드 복사
      -> 성공 toast: 링크를 복사했어요.
      -> 실패: 읽기 전용 URL 필드와 복사 안내
```

공유 payload:

```text
title: 재홍이네 반에 앉아봐
text: 재홍이네 반에 자리 하나 남았어. 너 어디 앉는지 한번 해봐!
url: https://서비스도메인/class/<shareCode>
```

공유 시트를 취소한 것은 오류 toast로 표시하지 않는다.

## 7. 친구의 링크 진입

```text
/class/:shareCode 직접 진입
  -> 교실 skeleton/도트 로딩
  -> 데이터 조회
    -> 성공: 현재 좌석표와 참여 폼
    -> 없음: 교실 not-found 화면
    -> 네트워크 실패: 다시 시도
```

상단:

```text
재홍이네 반
현재 4 / 9명
```

사용자는 입력 전에 이미 교실을 구경하고 책상을 눌러 기존 관계를 볼 수 있다.

## 8. 친구 참여

```text
별명 + 생년월일 입력
  -> 내 자리 찾기
  -> 클라이언트 검증
  -> 관계/캐릭터/선호 좌석 계산
  -> join_classroom RPC
    -> 성공
    -> 중복
    -> 만석
    -> 네트워크 오류
```

성공 시:

```text
문 열림
  -> 캐릭터 등장
  -> 목표 책상까지 이동
  -> 착석
  -> 이름표/관계 아이콘 표시
  -> 해당 좌석 BottomSheet 열림
```

RPC 응답의 최종 seat index를 애니메이션 목표로 사용한다. 요청 전에 계산한 후보 좌석으로 먼저 움직이지 않는다.

## 9. 참여 결과

BottomSheet:

```text
민수
재홍님의 뒷자리

공동피고인
좋은 선택보다 재밌는 선택을 같이 할 가능성이 높은 사람.

집중력 -38%  재미 +92%

[내 자리 결과 공유하기]
[나도 내 반 만들어보기]
```

- 공유는 현재 교실 링크와 참여자 관계 문구를 포함한다.
- `내 반 만들어보기`는 `/create`로 이동하며 기존 입력을 자동 복사하지 않는다.
- 재미용 수치는 실제 심리 측정 결과가 아니라는 점을 과장된 과학 표현 없이 전달한다.

## 10. 중복 참여

RPC가 기존 member id와 seat index를 반환한다.

```text
이미 이 반에 앉아 있어요!
  -> 입력 폼 닫기
  -> 기존 좌석으로 스크롤
  -> 800ms outline 강조
  -> 해당 관계 BottomSheet 열기
```

중복을 오류 화면으로 보내거나 새 좌석을 만들지 않는다.

## 11. 정원 완료

링크 진입 시 이미 9명이거나 참여 요청 직전에 마지막 좌석이 찰 수 있다.

```text
ClassroomFull
  -> 최신 교실 데이터 다시 조회
  -> 9석 완성 장면 표시
  -> 참여 폼 제거
  -> 결과 탐색 유지
  -> 내 반 만들기 CTA 강조
```

문구:

```text
이 반은 이미 꽉 찼어요!
그래도 내 반을 만들어볼래요?
[내 반 만들기]
```

## 12. 새로운 참여자 발견

기존 방문 이후 구성원이 추가됐는지는 로컬에 마지막으로 본 member id 목록을 저장해 비교한다.

```text
새로운 전학생이 왔어요!
```

가장 최근 새 좌석 하나를 잠깐 강조한다. 여러 명이 추가됐어도 알림을 연속 재생하지 않는다. Realtime 도입 전에는 페이지 재방문 또는 수동 새로고침 시 동작한다.

## 13. 교실 이미지 저장

```text
이미지 저장
  -> 캡처용 4:5 layout 구성
  -> 교실과 핵심 관계 요약 렌더링
  -> PNG 생성
  -> 파일 공유 지원?
    -> 예: 시스템 공유
    -> 아니오: 다운로드
```

캡처 중에는 입력 폼, 닫기 버튼, toast를 제외한다. 이미지 생성 실패 시 링크 공유 기능은 계속 사용할 수 있다.

## 14. 잘못된 링크와 만료

```text
앗, 교실을 못 찾았어요.
링크가 오래됐거나 잘못된 주소일 수 있어요.

[내 반 만들기]
[다시 시도]
```

존재하지 않음과 일시적 네트워크 오류를 내부적으로 구분한다. 만료된 교실 정책이 추가되면 같은 화면에서 `이 교실은 방과 후 문을 닫았어요.` 문구를 사용할 수 있다.

## 화면 전환 원칙

- 정상 흐름에서 브라우저 경고 dialog를 사용하지 않는다.
- 제출 중 버튼 label과 크기를 유지해 layout shift를 막는다.
- toast는 성공 피드백처럼 짧은 메시지에만 사용한다.
- 사용자가 해결해야 하는 오류는 입력 근처 또는 페이지 상태로 표시한다.
- 애니메이션은 2초 이내이며 reduced motion을 지원한다.
- 모든 실패 상태에서 사용자가 입력한 별명과 날짜를 가능한 한 유지한다.
